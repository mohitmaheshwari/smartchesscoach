# Refresh stored V5 captions

When you change the central caption pipeline (R12_blunder.json predicates, caption_facts.py extractors, R-rule selectors), already-analyzed games have STORED captions in `game_analyses.decryption_v5_data` generated by the OLD code. The system has a lazy-regen mechanism: when `stored_version < V5_COACHING_VERSION`, the per-move endpoint clears stale data and regenerates on next read.

This skill captures the bump-deploy-regen flow so the user sees the new captions without re-importing games.

## When to invoke

- User just shipped a caption / R12 / caption_facts change and asks "why don't I see it on existing games"
- User says "I deployed but the Insights tab still shows the old captions"
- User types `/refresh-v5-captions`
- After any commit touching: `backend/data/captions/*.json`, `backend/services/caption_pipeline.py`, `backend/services/caption_facts.py`, `backend/services/caption_rules.py`, `backend/services/caption_templates.py`, or any `R*.json` rule file

## Required input

- **What caption-side change just shipped.** Commit hash or 1-line description — used in the v100 note for V5_COACHING_VERSION.

## Steps

1. **Read the current V5_COACHING_VERSION from [backend/services/game_decryption_v5_service.py:48](backend/services/game_decryption_v5_service.py#L48).** The constant lives on line 48 with a long inline comment documenting v97/v98/v99/etc. history. Read just that line — the file is too large to read whole.

   ```bash
   awk 'NR==48 {print substr($0, 1, 80); exit}' backend/services/game_decryption_v5_service.py
   ```

2. **Bump the version by 1.** Use `Edit` to replace the line. Match the existing comment-history pattern — write a long inline comment documenting what changed in this bump. Style:

   ```python
   V5_COACHING_VERSION = N  # vN (YYYY-MM-DD): <what changed in 1-2 sentences>. <Why it requires regen>. <Linked commit hash or doc path>. <Previous note kept inline>...
   ```

   The note should mention the LINKED commit / spec / memory that triggered this bump. Mohit can grep for "v100" → finds the commit chain.

3. **Verify the bump landed.**

   ```bash
   awk 'NR==48 {print substr($0, 1, 60); exit}' backend/services/game_decryption_v5_service.py
   ```

   Should show the new version.

4. **Commit + push.** Title: `chore: bump V5_COACHING_VERSION <old> → <new> to force regen of stale captions`. Body: copy the inline note from the file + reference the originating commits.

5. **Tell the user the deploy + regen path:**

   ```bash
   # On server:
   git pull
   docker compose up -d --build backend
   ```

   Then explain: "To see the new captions on a specific game, open `/game/<game_id>` and **click the Review tab once** — that triggers the per-move endpoint at `/api/coach/decryption/per-move/{gameId}`, which detects `stored_version < V5_COACHING_VERSION`, clears the stale `decryption_v5_data`, and regenerates it with the new caption templates. After regen (~3-5 sec), the Insights tab will show fresh captions via Coach Review."

6. **Give a verification query the user can run** to confirm regen happened:

   ```bash
   docker exec chess-coach-backend python -c "
   import os, asyncio
   from motor.motor_asyncio import AsyncIOMotorClient
   async def m():
       db = AsyncIOMotorClient(os.environ['MONGO_URL'])[os.environ.get('DB_NAME','chess_coach')]
       a = await db.game_analyses.find_one({'game_id':'<GAME_ID>'}, {'_id':0,'decryption_v5_version':1})
       print('stored v5_version:', (a or {}).get('decryption_v5_version'))
   asyncio.run(m())
   "
   ```

   After Review tab visit + regen, this should print the NEW version number.

## Output format

After the commit + push:

1. The new V5_COACHING_VERSION number
2. The exact deploy commands (above)
3. The "visit Review tab" instruction (with the specific game URL if the user gave a game_id)
4. The verification query

## What NOT to do

- **Don't bump V5_COACHING_VERSION without an explanatory inline note.** The line is the audit trail for caption-pipeline changes; bumping with just a number breaks the convention.
- **Don't try to regenerate ALL games server-side via a script.** The lazy regen via per-move endpoint is the canonical path. Bulk regen scripts exist in `backend/scripts/batch_v5_regen.py` but are for one-off operational use; don't invoke them from this skill.
- **Don't bump the version on commits that don't actually change caption output.** Pure-test or pure-docs commits don't need a version bump.
- **Don't claim to have triggered regen yourself.** The skill instructs the user; the regen runs when the user (or any user) visits the Review tab. Skill doesn't have server access for this in most setups.
