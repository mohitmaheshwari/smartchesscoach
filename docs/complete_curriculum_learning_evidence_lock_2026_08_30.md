# Complete Curriculum — Learning Evidence Lock

Status: **LOCKED for the default-off implementation slice on 2026-08-30.**

Raw aggregate:
backend/data/corpus_snapshots/complete_curriculum_learning_evidence_2026-08-30.json.
It is a derived, aggregate-only measurement snapshot, not a new source of
curriculum truth or player mastery.

## Decision locked: selection and review cadence

**Value:** inherit the existing Personal Curriculum locks unchanged:

- five analyzed games before historical evidence can choose a personal repair;
- three occurrences of one named topic for Repair;
- one or two occurrences for an emerging Expand candidate;
- three fully measured games before evidence review;
- a 21-day check-in backstop that never claims new evidence.

**Evidence:** the versioned 2026-08-28 selection and review-opportunity
snapshots. Five games admit 39 of 46 measured users; Repair at three
occurrences admits 38 of 46; three-game windows contain at least six comparable
decisions in 99.05% of rolling windows; the game-gap p90 is 21 days.

**Rejected:** reopening these values from a newer live count without a
predeclared reason. The existing locks answer the same decision and are already
reproducible offline.

## Decision locked: what one lesson can prove

**Value:** one distinct, answer-hidden, unassisted checkpoint can prove **Can
do alone** for that exact skill version. A guided answer, repeated
demonstration, revealed candidate list, or answer recalled from the teaching
position cannot.

Where a compact reason or prediction is requested to distinguish likely
misconceptions, the move and reason must agree. A lucky correct move paired with
wrong reasoning remains unproven.

This is an existing semantic proof contract, not a tuned mastery threshold. It
comes from the approved truth-and-delivery scope and the current
CurriculumEvidenceEvent contract. It does not claim retention or real-game use.

## Decision locked: Used in games

**Value:** only an explicit, auditable application opportunity from a
quality-authorized detector can prove **Used in games**. The evidence must name
the game, move, opportunity outcome, detector identity, detector version, and
quality status.

Guided lesson play, a deliberately steered Coach position, and an organic user
game remain different sources. Coached application can be shown honestly but
cannot be relabeled as organic application.

**Rejected:** raw play count, opening exposure, a generic clean game, or an
LLM judgment. None proves that this skill had a real opportunity and was used.

## Decision locked: Reliable

**Value:** **no public promotion to Reliable in this implementation slice.**
The state and evidence events are implemented, but the promotion rule remains
closed until a clean instrumented cohort contains delayed independent recall
and source-qualified application outcomes.

**Evidence:** production contains 7,613 historical skill rows, but:

- 0 identify guided versus independent attempt kind;
- 0 carry a comparable delayed-review field;
- 0 carry a comparable evidence-source field;
- only 187 contain an auditable evidence artifact.

Those rows cannot distinguish candidate rules such as one, two, or three
independent successes, nor estimate later relapse by source. Any numeric
Reliable threshold selected from them would be invented.

**Rejected candidates:**

- one historical correct: conflates guided, repeated, and independent work;
- two or three historical correct values: same conflation with a cosmetic
  higher count;
- current learned_at: generated by inconsistent kind-aware legacy rules;
- elapsed days alone: creates a review without new evidence.

**Re-measurement requirement:** after the clean evidence schema records
attempt kind, assistance, content version, source, opportunity, outcome, and
delayed review, compare candidate Reliable rules by activation, later lapse,
help reduction, and organic application. Until then the honest ceiling is Used
in games, or Can do alone when application cannot be measured.

## Decision locked: personalized delivery

**Value:** use direct evidence precedence, not a fixed learning-style score:

1. the player's answer, prediction, or confusion in the current interaction;
2. verified evidence for this exact concept and content version;
3. the player's current game position, active focus, repertoire, and goal;
4. rating and general profile only as a complexity fallback.

When none of the first three exists, ask a short board-based diagnostic before
making a personal claim. Never infer a permanent “visual,” “verbal,” or
“practice” identity.

**Evidence:** only three of 69 production profiles contain a stored
learning-style value, while 58 contain game-derived weaknesses and 65 coach
memories contain skill progress. A global learning-style label has almost no
reach; direct game and skill evidence does.

**Rejected candidates:**

- fixed learning-style labels: sparse, unvalidated, and concept-insensitive;
- rating-only delivery: changes difficulty but still feels generic;
- LLM-selected personalization without an evidence trace: can invent history;
- one weighted personalization score: no outcome data exists to justify
  weights.

## Measurement method

Read-only full aggregates were run inside the production backend container,
using the container's existing Mongo environment. No sampling, credentials,
user identifiers, positions, moves, or free-form coaching text were exported.
The aggregate is versioned so implementation and review run offline.
