<analysis>**original_problem_statement:**
The user's high-level goal is to build a sophisticated, adaptive chess coaching application that acts as a thinking coach rather than just an engine analysis wrapper. The project has evolved from building features to refining the application's logic to diagnose and correct cognitive patterns and thinking errors.

Key user requests and product direction:
1.  **Eliminate Data Hallucinations:** The user has zero tolerance for incorrect or hallucinated analysis from the LLM, such as misidentifying tactical patterns or providing nonsensical explanations.
2.  **Focus on Human-Improvable Errors:** The application must distinguish between minor engine preferences and genuine, human-improvable mistakes (e.g., missed tactics, violated principles). The Lab should not be a list of all engine disagreements.
3.  **Implement a Cognitive Diagnosis-Prescription-Audit Loop:**
    *   **Diagnosis:** Analyze games to identify recurring cognitive weaknesses (e.g., Missed Forcing Moves, Phantom Threat Reaction) instead of just move-level errors.
    *   **Prescription:** Prioritize and recommend specific training drills (puzzles, traps) based on the user's primary diagnosed weakness.
    *   **Audit:** Track user progress against the focus weakness over a sliding window of games.
4.  **Shape User Behavior:** Frame feedback and coaching in actionable, behavioral terms (e.g., You are not scanning checks and captures consistently) rather than dry, analytical labels. Provide simple, 3-step protocols to correct habits.
5.  **Reduce UI Noise:** The UI should be sharp and focused, presenting only the primary weakness to avoid cognitive overload for the user.
6.  **Create a Thinking Stability Index (TSI):** Implement a derived metric that represents the stability of a user's decision-making process, complete with interpretive bands (e.g., Stable, High Volatility).
