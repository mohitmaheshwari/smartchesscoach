## Project context

**ChessGuru** is a coaching platform for 1200-1500 amateur chess
players. The product principle that drives every architectural
decision: **teach the thinking process, not just moves.** Named
geometric patterns + concrete consequences + transferable rules.
1200-1500 players REMEMBER named patterns (Pawn Fork, Rule of the
Square, The Opposition) — they don't remember move sequences from
specific games.

**Stack:** React frontend, FastAPI backend, MongoDB, Stockfish
analysis, OpenAI gpt-4.1-mini for LLM captions.

**Audience constraint** ([[1200-test for chess captions]] memory):
captions must use concrete pieces/squares/consequences only — no
chess jargon (outpost, fianchetto, controls, minority attack, luft,
repositions, "loses tempo", "loses initiative", "creates pressure",
"key squares"). A 1200 player must be able to verify the caption
by looking at the board.

## V5 caption pipeline architecture

This is the system the entire session has been refining. Five
modules, strict separation of concerns:

```
caption_facts.py          → Pure-Python detectors for 28 principles
                            + 24 shape patterns. Reads board+evidence,
                            emits structured evidence dicts. No LLM,
                            no chess advice — geometric truth only.

caption_priority_resolver.py → Pure-Python routing. Takes a move
                            record (with detector output), decides
                            which principle/shape/trap/opening/
                            mistake/category to ANCHOR the caption on.
                            Emits a decision dict with anchor name,
                            detail, secondary anchor, protected
                            entities, caption_mode (polish |
                            controlled_gen | silent), and more.

llm_caption_generator.py → Three-tier mode dispatch:
                            Tier 1 (polish):    LLM polishes the
                              deterministic draft caption while
                              preserving every protected entity
                            Tier 2 (controlled_gen): LLM builds
                              from anchor + punishment + allowed
                              entities (no draft to polish)
                            Tier 3 (silent):    return empty string

caption_verifier.py       → Post-LLM safety. Strips alt-suggestion
                            hallucinations, repairs disallowed
                            opening/shape names by substituting
                            move-role phrases, canonicalises
                            opening hyphens, enforces that every
                            protected entity survives in the
                            output (else falls back to the
                            deterministic draft).

shape_patterns.py +       → TIER 3 catalog of 24 geometric danger
shape_detectors.py +        patterns (Pawn Fork being the latest,
shape_layer.py              added this session). Each pattern has
                            data + detector + verifier.
```

**Locked rule** ([[renderer-never-computes-chess-meaning]]): chess
analysis (FEN parsing, PV walking, engine calls) lives ONLY in
caption_facts.py + shape_detectors.py. The resolver and renderer
read evidence dicts and never compute chess meaning themselves.

**Locked rule** ([[llm-as-controlled-narrator]]): LLM is a narrator,
not a reasoner. All routing decisions happen in Python BEFORE the
LLM is called. The LLM only verbalises a pre-resolved decision.
Three-tier mode never falls back to a monolithic prompt — that
architecture is what we're escaping.

## Three-tier mode + protected entities

Added 2026-05-16 after Mohit pushed back on the LLM building
captions from scratch.

**Tier 1 (polish):** When the move record has a deterministic
`caption` field, the LLM receives it as a "ground truth draft" plus
a list of protected entities (SAN moves, squares, piece words,
named patterns). The LLM polishes for voice but must preserve every
protected entity character-for-character. Engine talk ("loses N
pawns") gets replaced with concrete consequence.

**Tier 2 (controlled_gen):** When there's no draft, the LLM builds
from the resolver's anchor + punishment + allowed moves. This was
the only mode before the polish tier landed.

**Tier 3 (silent):** When `should_skip=True` or no anchor exists,
return empty string. Silence > filler.

**Protected entities:** computed by `_extract_protected_entities()`
in the resolver. Includes every SAN move, square name, piece word,
named pattern, punishment move, and allowed move from the draft +
resolver decision. The verifier enforces that every protected
entity appears in the LLM output; if any is missing, the verifier
falls back to the deterministic draft as-is.

## V5_COACHING_VERSION lazy regeneration

**Critical mechanic** ([[v5-lazy-generation-mechanic]] memory).
`decryption_v5_data` is NOT written by `analysis_worker.py`. It's
generated lazily by `routes/coach.py` when the frontend requests
per-move data, and only regenerated when `stored_version <
V5_COACHING_VERSION`.

**Current version: 7.** ANY change that adds a new field, detector,
or principle to the V5 data structure MUST bump V5_COACHING_VERSION
in the same commit. Otherwise the new code is dead for every
existing analyzed game until someone manually clears their
decryption_v5_data.

**To force regen for a single game:** run
`backend/scripts/regen_pilot.py` or unset the field manually:

```python
await db.game_analyses.update_one(
    {"game_id": gid},
    {"$unset": {"decryption_v5_data": "", "decryption_v5_version": ""}}
)
```

## Two filter passes on the audit (this is the key learning)

The audit pattern is non-negotiable per the locked rule:
[[per-fire-audit-pattern]] + [[no-yes-man]]. Pass 1 fired 135 times
across 3,738 games (geometric verification clean, 0 mismatches).
Manual review of sampled FENs showed **~75% pedagogical false
positives** — fires in positions where Chebyshev geometry holds but
the actual game is dominated by rooks/queens, making Rule of the
Square teaching irrelevant.

**Pass 2: material-purity gate.** Require no queens, no rooks, ≤1
minor piece per side. Dropped 135 → 13 fires.

**Pass 3: clear-runway filter.** Of the 13, two more false positives:
fire #6 (doubled pawn — a5 blocked by own a4) and fire #12 (d-pawn
blocked by own knight). Generalised filter requires the pawn's
promotion path to be fully clear. Expected to drop 13 → ~11.

This is the per-fire audit pattern that should be followed for
every Phase 3+ detector.

## NEW backlog item flagged 2026-05-17 (game review tone)

Mohit raised this just before switching laptops — separate from the
endgame principle work, different surface, save for AFTER Tier 1
endgame ships.

**Problem:** The cold mechanical labels at the top of game review
("Clean win", "You lost", "Threw a winning game") feel like a
computer printing a verdict, not a coach speaking. For 1200-1500
players who come to the review feeling vulnerable, a cold opener
triggers the close-the-tab reflex.

**Fix surface:** `backend/services/coach_action_service.py:21-32`
— the `DIAGNOSIS_LABELS` dict. 10 entries. Add a `warm_opener`
field to each (3-4 sentences: acknowledge + highlight positive
+ bridge + growth takeaway). Frontend renders `warm_opener` as
primary heading; `label` becomes a small category chip.

**Mohit-signed-off example pattern:**

> Clean win → "Well played! You outplayed your opponent from early
> on. Here's a look at your best moments — and one thing to sharpen
> for next time."
>
> Messy win → "You got the win — and that's what counts! It wasn't
> always smooth, but you found a way. Let's look at what worked and
> what to clean up."

**Guardrails:** no false praise (still honest about a bad game),
no advice tail per coach voice, no raw "blunder count" framing,
tone scales with severity (WON_CLEAN = pure positive; THROW =
empathy without sugar-coating).

**Estimated effort:** ~30 min strings + 1 frontend read change.
Author the messages WITH Mohit — don't fabricate solo.

Saved as `project_warm_result_summary.md` in memory.

   Split the caption pipeline so the deterministic resolver produces
   a "semantic IR" and the LLM does pure stylistic refinement. Solves
   the phrase-convergence problem ("claim the centre" appearing in
   60% of opening captions).

2. **Persistent coaching memory wire-up** (Phase 2)
   The `coach_memory` and `player_identities` MongoDB collections
   exist but aren't threaded into the LLM context path. Wiring them
   in would restore per-player calibration without growing the
   prompt. High ROI — wires up existing data, no new collections.

3. **Identity design / personality continuity** (Phase 3)
   Streak callbacks, "yesterday you played e4, today f4 — same
   plan?", timing of praise + silence after blunders. Overlaps with
   `project_situational_personality` (7 tones). Destination, not
   next step.

ChessGuru becomes identity design."
